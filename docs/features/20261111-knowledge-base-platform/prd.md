## 1. 背景与目标

- 背景：
  - 集团内各公司、部门的制度、产品资料、技术文档分散在个人电脑和网盘中，无法统一检索，也无法作为知识来源提供给内部系统和后续的大模型应用。
  - 用户希望参照 Dify 的"知识库"能力，建设企业自有的知识库平台：能看到有哪些知识库、每个知识库有多少文件、文件是怎么切分的；能通过 API 密钥让其他系统检索知识库。
  - 平台面向集团多公司使用，必须具备完整的登录认证、组织、角色权限和数据权限。这是本项目的第一个需求，地基能力（认证、组织、RBAC、数据权限）随本需求一并建设。
  - 用户希望权限认证、知识库管理、知识库检索、用户与模型聊天（二期）、后台文档处理等能力可以独立部署、独立扩展，便于平台长期演进。具体怎么拆由架构师在技术方案中设计。
- 目标：
  1. 建立集团统一的账号、组织、角色、数据权限体系，供后续所有业务模块复用。
  2. 让员工能自助创建知识库、上传文档、按规则切分（通用分段 / 父子分段）并建立索引，清楚看到每个知识库的文档与分段情况；由知识库所有者决定把知识库分配给哪些个人、部门、公司使用。
  3. 让知识库使用者能调整检索参数，并通过"召回测试"验证检索效果。
  4. 让员工用个人 API 密钥向内外部系统安全地开放知识库检索，检索范围与本人权限一致，每次调用都可追溯。
  5. 让管理员能按数据权限审计知识库，并在员工离职、调岗时转移知识库所有权。
- 成功标准（上线后 1 个月内可衡量）：
  1. 验收标准 AC-01 ~ AC-76 全部通过。
  2. 至少 1 家试点公司完成：建立组织与账号、创建 ≥3 个知识库、上传 ≥100 个文档，文档处理成功率 ≥95%（不计格式不支持和加密的文件）。
  3. 至少 1 个外部系统通过 API 密钥接入检索，调用日志可完整追溯。
  4. 测试中跨公司、跨部门、未分配的越权访问为 0 例。

## 2. 用户与场景

| 用户角色 | 典型场景 | 诉求 |
|---|---|---|
| 超级管理员（`super_admin`，系统内置） | 系统上线初始化：建立集团组织树、创建集团管理员、配置模型 | 一个不受限制的初始账号，用于开荒与兜底 |
| 集团管理员 | 维护集团及各子公司的组织；创建子公司管理员；维护集团级角色；配置向量/重排模型；审计全集团知识库，处理离职交接 | 全局可控，能穿透查看各子公司的知识库和调用情况 |
| 子公司管理员 | 维护本公司（含下属公司）的部门与员工账号、公司级角色；审计本公司知识库与 API 密钥；员工离职时转移其知识库 | 只管本公司，不被其他公司看到，也看不到其他公司 |
| 知识库所有者（任何有新建权限的员工） | 创建知识库、上传文档、设置分段、做召回测试；把知识库分配给同事、部门或公司（只读/可编辑） | 自己的知识自己做主，分配简单，处理进度可见 |
| 知识库使用者（被分配的员工） | 只读：查看内容、做召回测试；可编辑：上传文档、修正分段 | 能找到并使用分配给自己的知识 |
| 外部/内部业务系统（持某员工的 API 密钥调用，不登录） | 客服系统、OA、自研大模型应用按用户问题检索知识库片段 | 接口稳定、返回结构清晰，只能检索密钥持有人有权访问的知识库 |

## 4. 功能需求

### M1 平台地基

### F-01 登录认证与会话管理
- 描述：用户用账号 + 密码登录，支持登出、修改密码、登录态自动续期；系统初始化时提供超级管理员账号。
- 业务规则：
  1. 登录凭据为账号 + 密码（Q-05 已确认，不含验证码、短信、SSO）。
  2. 同一账号 15 分钟内连续输错密码 5 次，锁定 15 分钟。锁定期间即使密码正确也拒绝登录，并提示剩余锁定时间。登录成功后失败计数清零。
  3. 账号状态为"停用"，或其所属组织（或任一上级组织）为"停用"时，不能登录。
  4. 用户活跃期间登录态自动续期，无需重复登录；连续 7 天未使用需重新登录。访问令牌有效期 30 分钟（遵循 CLAUDE.md 5.1）。
  5. 登出后该会话立即失效。
  6. 发生以下情况时，该用户的**所有**会话立即失效、需要重新登录：修改密码、被管理员重置密码、账号被停用、账号被删除。
  7. 密码规则：8~32 位，必须同时包含字母和数字；新密码不能与当前密码相同。
  8. 系统初始化时生成超级管理员账号 `admin`，**首次登录必须先改密码**才能使用其他功能。被管理员重置密码的用户同样要在首次登录时改密。
  9. 登录成功和失败（含失败原因）都写登录日志。
- 输入 / 输出：输入账号、密码；登录成功后进入首页，加载当前用户信息、菜单和权限码。
- 异常与边界：
  - 账号不存在和密码错误统一提示"账号或密码错误"，不暴露账号是否存在。
  - 登录态过期时，如果自动续期成功，用户无感知；续期失败则跳转登录页，重新登录后回到原页面。
  - 重复点击登录按钮只提交一次。
- 关联验收：AC-01 ~ AC-06

### F-02 组织管理
- 描述：维护"集团 → 公司（可多级子公司）→ 部门"的统一组织树。
- 业务规则：
  1. 组织类型：集团（全系统只有 1 个根节点，初始化时创建）、公司、部门。集团节点同时代表"集团本部"。
  2. 层级约束：公司的上级只能是集团或公司；部门的上级可以是集团、公司或部门（集团节点可以直接下设部门，即集团本部的部门）；部门下不能建公司。
  3. 同一上级下组织名称唯一；组织编码全局唯一。
  4. 组织可以"停用"：停用后其下所有组织都视为停用，其下用户不能登录（F-01 规则 3）。停用不影响数据归属。
  5. 删除：组织下还有下级组织、归属用户或归属知识库时不能删除，需要先迁移或删除；删除为逻辑删除。
  6. 允许调整上级组织（移动），移动后其下用户、知识库的"所属公司"随之重新计算。不能移动到自身或自身的下级之下；公司不能移动到部门下。
  7. 子公司管理员只能查看和维护本公司及其下属组织，不能修改本公司节点自身的上级和类型，不能新建同级公司。
  8. 同级组织按"显示顺序"升序排列，顺序相同时按创建时间排列。
  9. 管辖根组织保护（TQ-06）：
     - "管辖根组织"是指管理员的数据范围所覆盖的最上层组织节点，例如：`COMPANY_AND_CHILD`/`COMPANY` 为本公司节点；`DEPT_AND_CHILD`/`DEPT` 为本部门节点；`CUSTOM` 为所勾选节点中不被其他勾选节点包含的各个节点。多角色时，各角色的管辖根组织都受保护。
     - 不是超级管理员、且数据范围不是 `ALL` 的管理员，不能停用、删除自己的管辖根组织；
     - 任何人（含超级管理员）都不能停用本人所在的组织，也不能停用其任一上级组织；
     - 需要时由上级管理员操作。
     - 页面上这些节点的"停用""删除"按钮置灰，悬停提示原因；直接请求会被拒绝。
- 输入 / 输出：见第 6 节"组织"实体。
- 异常与边界：
  - 两人同时编辑同一组织时，如果后提交者基于过期数据，提示"数据已被他人修改，请刷新后重试"。
  - 组织树节点数按上限 5000 设计（见第 8 节）。
- 关联验收：AC-07 ~ AC-09、AC-74

### F-03 用户管理
- 描述：管理员维护自己管辖范围内的用户账号。
- 业务规则：
  1. 一人一主组织：用户必须归属一个集团、公司或部门节点；"所属公司" = 向上最近的公司节点（遵循 CLAUDE.md 5.2）。如果向上没有公司节点（即用户直接归属集团节点，或归属集团本部的部门），所属公司 = 集团节点，即"集团本部"。
  2. 账号全局唯一（已删除账号也不能复用），创建后不能修改。账号**区分大小写**：`Alice` 与 `alice` 是两个不同的账号，可以同时存在；登录时账号必须与注册时的大小写完全一致（M1 测试中用户确认）。
  3. 新增用户时，由管理员设置初始密码，或由系统生成随机密码并只展示一次；用户首次登录须改密。
  4. 操作：新增、编辑、停用/启用、重置密码、分配角色、删除（逻辑删除）。
  5. 管理员不能停用或删除自己，不能删除超级管理员账号。
  6. 一个用户可以有多个角色；可分配的角色范围见 F-04 规则 4。
  7. 管理范围：管理员能管理的用户 = 其角色数据范围内的用户（例如数据范围为 `COMPANY_AND_CHILD` 的子公司管理员，管理本公司及下属公司的全部用户）。
  8. 用户列表支持按组织树筛选：点击左侧组织节点，显示该节点及其下级的用户。
  9. 用户停用或删除时，以下联动规则见 F-20 规则 5 和 F-17 规则 7：其拥有的知识库保留、分配继续生效，在管理视图中标记"所有者已停用/已删除"，等待转移；其 API 密钥失效。
- 输入 / 输出：见第 6 节"用户"实体。
- 异常与边界：
  - 被停用用户正在使用的会话立即失效。
  - 本期不做批量导入。
- 关联验收：AC-10 ~ AC-12

### F-04 角色与权限管理
- 描述：维护角色，为角色分配菜单/按钮权限和数据范围。
- 业务规则：
  1. 权限点（菜单、按钮、接口）由系统预置并随版本发布，不提供界面新增或删除；角色管理页以权限树形式勾选。
  2. 角色分为两类：
     - 集团级角色：由集团管理员维护，可分配给全集团任意用户；
     - 公司级角色：归属某公司，由该公司（或上级公司）的管理员维护，只能分配给该公司及其下属公司的用户。
  3. 角色属性：名称、编码、类型（集团级/公司级）、所属公司（公司级必填）、数据范围（7 种之一，见 F-05）、自定义组织（数据范围为 CUSTOM 时必选）、状态、备注。
  4. 授权上限：
     - 管理员给角色勾选的权限不能超出自己拥有的权限；
     - 管理员只能给用户分配自己可见的角色，且该角色的权限不能超出自己的权限；
     - 可设置的数据范围不能大于自己的数据范围（例如 `COMPANY_AND_CHILD` 的管理员不能创建 `ALL` 的角色）。
  5. 内置角色在系统初始化时创建，不能删除。除 `super_admin` 外权限可以调整。

     | 内置角色 | 类型 | 默认数据范围 | 默认权限 |
     |---|---|---|---|
     | 超级管理员 `super_admin` | 集团级 | 不受限 | 全部，跳过所有校验 |
     | 集团管理员 | 集团级 | ALL | 除超级管理员专属外的全部权限 |
     | 公司管理员（模板） | 集团级 | COMPANY_AND_CHILD | 本公司系统管理、知识库管理视图与所有权转移、API 密钥审计，以及普通员工的全部权限 |
     | 普通员工 | 集团级 | SELF | 知识库新建与日常使用（查看/编辑/分配/删除自己的知识库）、召回测试、个人 API 密钥 |

     数据范围只影响"管理类"能力（用户/组织/角色管理、知识库管理视图、API 密钥审计、日志），**不影响**员工日常能访问哪些知识库（见 F-05 规则 6）。
  6. 角色停用后，持有该角色的用户从下一次请求起失去该角色的权限。
  7. 角色仍有关联用户时不能删除，需先解除关联。
  8. 权限变更在用户刷新页面或下一次请求时生效，无需重新登录。
- 输入 / 输出：见第 6 节"角色"实体。
- 异常与边界：
  - 管理员修改自己所持的角色，导致自己失去角色管理权限时，弹出二次确认"保存后您将失去该页面权限"。
  - 角色编码全局唯一；同一公司内角色名称唯一。
- 关联验收：AC-13 ~ AC-16

### F-05 数据权限
- 描述：受数据权限控制的数据，按用户角色的数据范围过滤管理员"可见、可管理"的范围。本期受控数据：用户、组织、知识库（管理视图）、API 密钥（审计）、API 调用日志、操作日志。
- 业务规则：
  1. 7 种数据范围（遵循 CLAUDE.md 5.4）：

     | 数据范围 | 可见/可管理的数据 |
     |---|---|
     | ALL 全部 | 全部 |
     | COMPANY_AND_CHILD 本公司及下属公司 | 数据所属公司为本公司或其下属公司 |
     | COMPANY 本公司 | 数据所属公司 = 本人所属公司 |
     | DEPT_AND_CHILD 本部门及以下 | 数据所属部门为本人所属部门或其下级部门 |
     | DEPT 本部门 | 数据所属部门 = 本人所属部门 |
     | SELF 仅本人 | 数据的"本人"为当前用户（知识库：当前所有者；API 密钥：创建人；其余：创建人）。两处例外：**用户列表**额外包含本人账号；**组织树**额外包含本人所在组织及其全部上级组织，这些组织仅作只读展示，不因此获得管理权限（见规则 8） |
     | CUSTOM 自定义组织 | 数据所属组织在角色配置的组织集合内。勾选某节点不自动包含下级，界面提供"包含下级"快捷勾选 |

  2. 用户有多个角色时，数据范围取其所有**启用**角色的并集（停用的角色不参与计算）。并集后的数据范围对该用户拥有的**所有**功能权限生效，与某项功能权限来自哪个角色无关（与若依一致）。例如：角色 R1 提供"用户管理"功能、数据范围为 DEPT，角色 R2 只提供"知识库管理视图"功能、数据范围为 COMPANY，则该用户在用户管理中可以看到本公司的用户。
  3. 超级管理员不受数据范围限制。
  4. 用户直接归属公司节点或集团节点（不属于任何部门）时：`DEPT` 只看归属在该节点本身的数据；`DEPT_AND_CHILD` 包含该节点下的全部部门，但不含下属公司。集团节点即"集团本部"，`COMPANY` 对集团本部的用户只覆盖集团本部（集团节点及其直属部门）的数据，不含各子公司。
  5. 数据归属：
     - 一般数据的所属公司/部门，取**创建时**创建人所在的组织；创建人之后调岗，不改变已有数据的归属。
     - 知识库的所属公司/部门取**所有者**所在的组织：创建时为创建人的组织；所有权转移后，改为新所有者当时所在的组织（F-20）。
  6. **知识库的日常访问不由数据范围决定**（Q-02 已确认）：
     - 日常访问 = 所有者 + 被分配的个人 + 被分配部门/公司的成员（F-10）；
     - 数据范围只决定管理员在"知识库管理视图"中能审计哪些知识库、能转移哪些知识库的所有权（F-20）；
     - 管理视图中的"可见"不会让知识库出现在管理员的日常知识库列表中，也不扩大其 API 密钥的检索范围（F-17）。
  7. 越权访问（例如直接构造链接访问不可见的数据）统一返回"无权限或数据不存在"，不暴露数据是否存在。
  8. SELF 的两处例外（M1 测试中用户确认）：
     - 用户列表：可见 = 本人创建的用户 + 本人账号。对本人账号能做的操作，仍受功能权限、F-03 规则 5（不能停用或删除自己）和 F-04 规则 4（不能越权授权）约束。
     - 组织树：可见 = 本人创建的组织 + 本人所在组织及其全部上级组织（用于展示归属路径）。这些额外可见的组织只读展示：不显示、也不允许编辑、新增下级、停用、删除、移动；不作为该用户的管辖范围；不使其下的用户或数据变为可见。
     - 其他业务数据（知识库管理视图、API 密钥审计、调用日志、操作日志等）不适用这两处例外，仍按规则 1 中"本人"的定义。
- 关联验收：AC-17 ~ AC-19、AC-75、AC-76

### F-06 操作日志与登录日志
- 描述：记录关键操作和登录行为，供管理员审计查询。
- 业务规则：
  1. 登录日志字段：账号、结果（成功/失败）、失败原因、IP、浏览器/客户端、时间。
  2. 操作日志必须覆盖以下操作：
     - 用户：新增、编辑、停用/启用、重置密码、删除、分配角色；
     - 角色：新增、编辑、权限变更、数据范围变更、删除；
     - 组织：新增、编辑、移动、停用、删除；
     - 模型配置：新增、编辑、删除；
     - 知识库：新建、删除、分配变更、所有权转移、检索设置变更、管理员在管理视图中查看内容；
     - 文档：上传、删除、重新分段；
     - API 密钥：创建、修改检索范围、停用/启用、重新生成、删除（含管理员处置他人的密钥）。
  3. 每条操作日志的字段：操作人、操作人所属公司、模块、操作类型、操作对象（名称 + 标识）、变更摘要（关键字段的变更前后值）、结果（成功/失败）、IP、时间。
  4. 日志只能查询，不能修改或删除；保留 180 天（Q-08 已确认）。
  5. 日志查询受数据权限控制，按操作人所属组织计算。
- 异常与边界：日志写入失败不能阻塞业务操作，但需要在系统运行日志中报错。
- 关联验收：AC-20 ~ AC-21

### M2 知识库

### F-07 模型配置
- 描述：集团管理员配置平台可用的向量（Embedding）模型和重排（Rerank）模型，供知识库建索引和检索使用。
- 业务规则：
  1. 模型类型：Embedding、Rerank（LLM 二期再做）。
  2. 统一按"OpenAI 兼容接口"协议接入，既可以填私有化部署的地址，也可以填云厂商的地址（Q-04 已确认）。
  3. 字段：显示名称、模型类型、服务地址、模型标识、访问凭据（保存后界面只显示掩码）、Embedding 向量维度（Embedding 必填，可通过"测试连接"自动获取）、单次最大输入长度、状态（启用/停用）、是否默认。
  4. 保存前须"测试连接"通过；测试失败的模型可以保存为"停用"状态，但不能启用。
  5. 每种类型最多一个"默认模型"，新建知识库时默认选中。
  6. 模型配置是全平台共享资源，只有集团管理员和超级管理员可以维护。其他用户在知识库中只能"选择"已启用的模型，看不到服务地址和凭据。
  7. 被任一知识库使用的 Embedding 模型不能删除，也不能修改服务地址、模型标识、维度，只能停用。停用后，使用它的知识库不能上传新文档、不能检索，知识库页面提示"向量模型已停用，请联系管理员"。
  8. 被使用的 Rerank 模型停用后，开启了 Rerank 的检索自动降级为不重排，并在召回测试结果中提示"重排模型不可用，已跳过重排"。
  9. 用户未指定具体模型。模型配置页提供推荐示例，仅用于引导填写，不预置为可用模型：Embedding 示例 `bge-m3`（维度 1024，最大输入 8192 tokens）；Rerank 示例 `bge-reranker-v2-m3`。
- 异常与边界：模型服务调用超时或报错时，文档处理进入失败状态（F-12），检索返回明确的错误（F-16、F-18）。
- 关联验收：AC-22 ~ AC-24

### F-08 我的知识库列表
- 描述：展示当前用户日常可访问的知识库，以及每个知识库的文件数、分段方式等核心信息。
- 业务规则：
  1. 列表范围 = 本人拥有的 + 分配给本人的 + 分配给本人所在部门/公司的知识库（F-05 规则 6）。
  2. 每个知识库卡片/行展示：名称、描述（最多 2 行）、文档数、分段数、总字符数、分段方式（通用分段 / 父子分段）、索引方式（"高质量"）、检索方式（向量/全文/混合）、所有者、我的权限（所有者/可编辑/只读）、最近更新时间。
  3. 文档数只统计未删除的文档，包含处理中和失败的文档。卡片上另外显示"处理中 x / 失败 y"，为 0 时不显示。
  4. 分段数和总字符数只统计"可用"状态文档的分段（含已禁用的分段）。父子分段的知识库显示"父块 x / 子块 y"。
  5. 查询条件：名称关键字（模糊匹配）、我的权限、所有者、分段方式；另有"仅看我拥有的"快捷开关。
  6. 排序：默认按最近更新时间倒序，可切换为按名称、按文档数排序。
  7. 展示方式：卡片视图（默认）/ 列表视图切换；每页 20 条（卡片视图 24 条）。
- 关联验收：AC-25 ~ AC-27、AC-66

### F-09 知识库创建、编辑、删除
- 描述：创建空知识库，配置基础信息、向量模型和默认检索设置；编辑；删除。
- 业务规则：
  1. 创建字段：名称（必填）、描述、图标（可选，从预置图标库选择）、Embedding 模型（默认为默认模型）、检索设置（F-15，有默认值）。
  2. 创建人自动成为**所有者**。知识库记录所有者的所属公司和部门（F-05 规则 5），这些信息不能手动修改。
  3. 名称在同一所有者名下唯一（推荐假设 A-17）。
  4. 分段方式（通用分段 / 父子分段）在**第一次上传文档时**选定，此后该知识库的所有文档都使用这种方式，具体参数可以按文档调整。删除全部文档后可以重新选择（推荐假设 A-18）。
  5. 编辑：名称、描述、图标、检索设置可以随时修改。Embedding 模型只有在知识库内**没有任何文档**时才能修改。
  6. 删除：二次确认，需输入知识库名称。删除后知识库及其文档、分段一并逻辑删除，正在处理的文档任务取消，所有分配记录失效。
  7. 只有所有者（以及超级管理员）可以删除。管理员不能直接删除他人的知识库，需要先转移所有权（F-20）。
  8. 新建知识库需要"新建知识库"功能权限。普通员工默认拥有，管理员可以通过角色收回（Q-02 已确认）。
- 异常与边界：
  - 删除时，确认弹窗提示"共有 x 个分配对象将失去访问权限"。
  - 删除与他人的上传操作并发时以删除为准，上传任务失败并提示"知识库已删除"。
- 关联验收：AC-28 ~ AC-32

### F-10 知识库分配
- 描述：所有者把知识库分配给个人、部门或公司，并设定只读或可编辑权限（Q-02 已确认）。
- 业务规则：
  1. 知识库权限级别：

     | 级别 | 来源 | 能做什么 |
     |---|---|---|
     | 所有者 | 创建人，或所有权转移的接收人 | 全部操作：编辑设置、上传/删除文档、分段编辑、分配、删除知识库 |
     | 可编辑 | 分配 | 上传/删除文档、重新分段、分段编辑与启停、召回测试、修改检索设置；不能分配、不能删除知识库、不能修改向量模型 |
     | 只读 | 分配 | 查看文档列表和分段内容、下载原文件、召回测试（临时调整参数，不能保存为默认） |

  2. 分配对象有三类：
     - 个人：指定用户；
     - 部门：部门节点，可选"包含下级部门"；
     - 公司：公司节点，可选"包含下属公司"（默认不含下属公司）。
  3. 同一用户通过多个途径获得权限时，取最高级别。
  4. 分配权限仍受角色功能权限约束：例如角色没有"上传文档"权限，即使被分配了可编辑也不能上传。
  5. 分配范围（推荐假设，见 Q-09）：所有者只能分配给**本人所属公司及其下属公司内**的个人、部门、公司；所有者所属公司为集团本部（即直接归属集团节点，或归属集团节点直属的部门及其下级部门，见 F-02 规则 2、F-03 规则 1）时，可分配给全集团任意组织和个人。
  6. 只有所有者可以新增、修改、移除分配。可编辑用户可以查看分配名单，但不能修改。
  7. 分配、修改、移除即时生效。
  8. 按部门/公司分配时成员动态生效：新加入该组织的员工自动获得权限，调出的员工自动失去权限。
- 异常与边界：
  - 被分配的用户或组织被删除后，相关分配记录自动失效。
  - 不能把知识库分配给所有者本人。
  - 所有权转移后，原所有者是否保留访问权限见 F-20 规则 3。
- 关联验收：AC-33 ~ AC-35

### F-11 文档上传与分段设置
- 描述：向知识库上传文件，选择分段规则并预览效果，确认后提交后台处理。
- 业务规则：
  1. 支持的文件类型（Q-06 已确认）：TXT、Markdown、PDF（文本型）、DOCX、XLSX/XLS、CSV、HTML、PPTX。
  2. 单文件不超过 15 MB；一次最多选择 20 个文件；单个知识库最多 10,000 个文档。
  3. 同一知识库内文件内容完全相同（不论文件名）视为重复，拒绝上传，并提示已存在的文档名；文件名相同但内容不同的允许上传。
  4. 上传为三步向导：①选择文件 → ②分段设置与预览 → ③处理进度。
  5. 分段方式（Q-07 已确认：通用 + 父子）：知识库首次上传时二选一，之后固定（F-09 规则 4）。一次上传的文件共用一套设置。
  6. **通用分段**设置：

     | 设置项 | 规则 | 默认值 |
     |---|---|---|
     | 分段标识符（分隔符） | 1~10 个字符，支持 `\n`、`\n\n` 等转义写法 | `\n\n` |
     | 分段最大长度 | 50 ~ 4000 tokens 的整数，且不超过所选 Embedding 模型的单次最大输入 | 1024 |
     | 分段重叠长度 | 0 ~ 最大长度 50% 的整数 | 50 |

     切分方式：先按分隔符切分；单段仍超过最大长度时，再按最大长度继续切分，并保留重叠部分。
  7. **父子分段**设置：子块用于检索匹配，命中后返回其所在父块的完整内容作为上下文。

     | 设置项 | 规则 | 默认值 |
     |---|---|---|
     | 父块模式 | 段落：按分隔符把文档切成多个父块；全文：整篇文档作为一个父块 | 段落 |
     | 父块分隔符（段落模式） | 1~10 个字符，支持转义写法 | `\n\n` |
     | 父块最大长度（段落模式） | 50 ~ 4000 tokens 的整数 | 1024 |
     | 子块分隔符 | 1~10 个字符，支持转义写法 | `\n` |
     | 子块最大长度 | 20 ~ 父块最大长度的整数（全文模式时上限 4000），且不超过 Embedding 模型的单次最大输入 | 512 |

     - 子块不设重叠。
     - 全文模式只适用于不超过 10,000 tokens 的文档；超过时预览给出提示，并要求改用段落模式（推荐假设 A-19）。
  8. 文本预处理（两种分段方式共用）：
     - 替换连续空格、换行符和制表符（默认开）；
     - 删除所有 URL 和电子邮件地址（默认关）。
  9. 提供"使用该知识库上次的设置"和"恢复默认"两个快捷操作。
  10. 预览：选择任一已选文件，展示前 10 个分段。通用分段显示序号、字符数、内容；父子分段显示父块，展开可看子块。预览结果与实际处理结果一致。
  11. 确认后文件进入后台处理，用户可以离开页面，处理不受影响。
- 异常与边界：
  - 不支持的文件类型、超出大小、空文件、加密或损坏的文件：在第①步提示并剔除，其余文件可以继续。
  - 预览时文件无法解析（如扫描版 PDF 没有文本）：提示"未能从文件中提取到文本"，该文件不能提交。
  - 上传过程中网络中断：已上传完成的文件保留；未完成的文件提示失败，可重试。
- 关联验收：AC-36 ~ AC-39、AC-63

### F-12 文档处理任务与状态
- 描述：后台异步完成"解析 → 分段 → 向量化与建索引"，前端可以看到进度和状态。
- 业务规则：
  1. 文档状态依次为：排队中 → 解析中 → 分段中 → 索引中 → 可用；任一步骤出错则进入"失败"。
  2. 只有"可用"状态的文档参与检索。
  3. 索引中显示进度：已完成分段数 / 总分段数（父子分段按子块计数）。
  4. 失败时展示可读的原因（如"文件无可提取文本""向量模型调用超时""向量模型已停用"），并可"重试"；重试从失败步骤所在的阶段重新开始。
  5. 文档列表和处理页面自动刷新状态（无需手动刷新），直到所有文档进入终态（可用或失败）。
  6. 处理中的文档可以删除（即取消处理），但不能重新分段，也不能编辑分段。
- 异常与边界：
  - 平台重启或处理节点故障后，未完成的任务应自动恢复或标记失败，不能一直停在处理中。判定标准：任一中间状态停留超过 30 分钟且没有进度变化，标记为失败"处理超时"，可重试。
- 关联验收：AC-40 ~ AC-41

### F-13 文档管理
- 描述：在知识库详情中查看和管理文档。
- 业务规则：
  1. 文档列表列：文件名、文件类型、分段方式、字符数、分段数（父子分段显示"父块/子块"）、召回次数、上传人、上传时间、处理状态、启用状态、操作。
  2. "召回次数" = 该文档的分段在召回测试和开放检索 API 中被返回的累计次数。
  3. 查询条件：文件名关键字、处理状态、启用状态。排序：上传时间（默认倒序）、字符数、召回次数。
  4. 操作：查看分段、启用/禁用、重新分段（修改分段设置后重新处理，只能在本知识库的分段方式内调整参数）、下载原文件、删除；支持批量启用、禁用、删除。
  5. 禁用文档后，其所有分段都不参与检索，数据保留，可以重新启用。
  6. 重新分段会**丢弃该文档全部现有分段及人工修改**，二次确认后重新进入处理流程；处理完成前，该文档不参与检索。
  7. 删除文档时分段一并删除，知识库统计同步更新。
- 关联验收：AC-42 ~ AC-44、AC-66

### F-14 分段查看与编辑
- 描述：查看某个文档的全部分段，并进行修正。
- 业务规则：
  1. 通用分段列表：序号、内容（默认折叠显示前 3 行，可展开）、字符数、召回次数、启用状态。支持按内容关键字搜索、按启用状态筛选。
  2. 编辑通用分段：内容长度为 1 ~ 最大分段长度。保存后该分段重新向量化，完成前检索仍使用旧内容，状态显示"索引更新中"。
  3. 分段关键词：每个通用分段可以维护 0~10 个关键词，每个不超过 20 字，用于全文检索加权，由人工维护，系统不自动抽取。
  4. 新增分段：追加在文档末尾，规则与编辑相同。
  5. 单个分段可以启用/禁用，也可以删除（需二次确认）。
  6. 人工编辑过的分段标记"已编辑"。
  7. **父子分段**：
     - 列表以父块为单位展示，展开后显示其子块；
     - 编辑父块内容后，系统按该文档的子块设置**自动重新生成其子块**，该父块下的子块人工修改会被丢弃（需二次确认）；
     - 子块可以单独编辑、新增、删除，长度为 1 ~ 子块最大长度；
     - 启用/禁用以父块为单位：禁用父块后，其所有子块都不参与检索；
     - 父子分段不维护关键词（推荐假设 A-20）。
- 异常与边界：
  - 两人同时编辑同一分段时，如果后保存者基于旧版本，提示"该分段已被他人修改"，不覆盖。
- 关联验收：AC-45 ~ AC-47、AC-65

### F-15 检索设置
- 描述：每个知识库配置默认的检索方式和参数，作为召回测试和开放检索 API 的默认值。
- 业务规则：
  1. 检索方式：
     - 向量检索：按语义相似度检索；
     - 全文检索：按关键词匹配；
     - 混合检索：同时执行向量检索和全文检索，再合并结果。合并方式二选一：按"权重"合并（语义权重 0~1，步长 0.1，默认 0.7，关键词权重 = 1 − 语义权重），或使用 Rerank 模型重排。
  2. 通用参数：

     | 参数 | 取值 | 默认 |
     |---|---|---|
     | Top K（返回条数上限） | 1 ~ 20 的整数 | 3 |
     | Score 阈值 | 开关；开启时 0 ~ 1，步长 0.01 | 关；开启后默认 0.5 |
     | Rerank（向量检索、全文检索时可选开启） | 开关 + 选择已启用的 Rerank 模型 | 关 |

  3. 开启 Score 阈值后，得分低于阈值的结果不返回（即使不足 Top K 条）。
  4. 没有任何启用状态的 Rerank 模型时，Rerank 开关置灰并给出提示。
  5. 父子分段的知识库：检索时匹配子块，返回子块所在的父块。同一父块有多个子块命中时合并为一条结果，得分取命中子块中的最高分。Top K 按父块条数计算，Score 阈值按子块得分判断。
  6. 所有者和可编辑用户可以修改默认检索设置。
- 关联验收：AC-48 ~ AC-49、AC-64

### F-16 召回测试
- 描述：在页面中输入问题，查看知识库按检索设置召回的分段，用于验证分段和检索效果。
- 业务规则：
  1. 输入：问题文本 1 ~ 500 字。可以临时调整检索设置，仅本次测试生效；所有者和可编辑用户可以把它"保存为知识库默认设置"。
  2. 输出：命中结果按得分降序排列，每条显示得分（保留 2 位小数）、内容、所属文档名、分段序号，点击可查看详情。父子分段的知识库显示父块内容，并高亮其中命中的子块。
  3. 每人在每个知识库保留最近 20 条测试记录（问题、检索方式、时间），可以查看并一键重新测试；记录仅本人可见。
  4. 召回测试计入"召回次数"统计。
- 异常与边界：
  - 无命中时显示"未召回到相关内容，可尝试降低 Score 阈值或调整分段"。
  - 知识库没有可用文档时，测试按钮置灰并给出提示。
  - 模型服务异常时显示明确的错误信息，不能用空结果误导用户。
- 关联验收：AC-50 ~ AC-51

### F-20 知识库管理视图与所有权转移
- 描述：管理员按自己的数据范围审计知识库，并在员工离职、调岗时转移所有权（Q-02 已确认）。管理员不参与知识库的日常分配。
- 业务规则：
  1. 拥有"知识库管理视图"功能权限的用户（默认为公司管理员、集团管理员）可以在"系统管理 > 知识库管理"中看到数据范围内的全部知识库。数据范围按知识库的所属公司/部门计算，SELF 指当前所有者为本人。
  2. 管理视图可见内容（推荐假设，见 Q-10）：
     - 元信息：名称、所有者（含账号状态）、所属公司/部门、文档数、分段数、分段方式、分配名单、创建时间、最近更新时间；
     - **只读**查看文档列表和分段内容（审计用途，每次进入查看内容都记操作日志）；
     - 不能上传、编辑、删除文档，不能修改设置或分配，不能删除知识库，不能做召回测试；
     - 该知识库不会因此出现在管理员的"我的知识库"中，也不进入其 API 密钥的检索范围。
  3. 所有权转移：
     - 管理员可以把数据范围内的知识库转移给另一个用户，接收人须在管理员的数据范围内，且账号为启用状态；
     - 转移后，接收人成为所有者，知识库的所属公司/部门改为接收人当时所在的组织；
     - 已有的分配记录保持不变；
     - 原所有者失去所有者身份，不保留访问权限（如需保留，由新所有者重新分配）；
     - 所有者本人也可以把自己的知识库转移给本公司及下属公司内的其他用户（推荐假设 A-21）。
  4. 支持批量转移：选择某位用户名下的全部知识库，一次转移给同一个接收人（离职交接场景）。
  5. 所有者被停用或删除时，其知识库照常可用，已有分配继续生效（推荐假设，见 Q-14）。管理视图中以"所有者已停用/已删除"标记，并提供"待交接"快捷筛选。
  6. 管理视图的查询条件：名称、所有者、所属组织（树选择）、所有者状态（正常/已停用/已删除）。
- 异常与边界：
  - 转移给自己（管理员本人）是允许的，转移后管理员作为所有者获得全部权限，包括删除。
  - 接收人名下已有同名知识库时，转移被拒绝，并提示"接收人已有同名知识库，请先改名"。
  - 转移与所有者的编辑操作并发时，以转移为准；原所有者的后续操作被拒绝。
- 关联验收：AC-67 ~ AC-69

### F-17 个人 API 密钥管理
- 描述：员工创建自己的 API 密钥，供业务系统调用开放检索 API。密钥的检索范围由创建人自身的权限决定（Q-03 已确认）。
- 业务规则：
  1. 拥有"API 密钥"功能权限的用户都可以创建自己的密钥。普通员工默认拥有该权限，管理员可以通过角色收回（推荐假设 A-22）。
  2. 密钥属于创建人个人，不能转移。
  3. **检索范围**（推荐假设，见 Q-11）：
     - 范围上限 = 创建人**当前**日常可访问的知识库（所有者 + 被分配，只读即可），实时跟随创建人的权限变化；
     - 管理视图的审计可见范围（F-20）**不计入**；超级管理员的密钥同样遵循此规则；
     - 创建时可以选择两种范围之一：
       - "我可访问的全部知识库"（默认）：之后新获得的知识库自动纳入；
       - "指定知识库"：从本人当前可访问的知识库中勾选 1~50 个。
     - 在"指定知识库"模式下，如果创建人后续失去某个知识库的访问权，该知识库自动不可检索；重新获得权限后自动恢复。
  4. 密钥字段：名称（必填，同一创建人名下唯一）、用途说明、检索范围、过期时间（永不过期 / 指定日期，默认 1 年）、IP 白名单（可选，最多 20 条，支持单个 IP 和网段）、每分钟调用上限（默认 60，可设 1 ~ 600，Q-08 已确认）、状态。
  5. 密钥明文**只在创建成功时显示一次**，提供复制按钮；之后只显示前缀 + 掩码（如 `kb-AbCd****`）。遗失后只能"重新生成"，旧值立即失效。
  6. 创建人可以：编辑（名称、说明、检索范围、过期时间、IP 白名单、调用上限）、停用/启用、重新生成、删除。停用、删除、重新生成立即生效。
  7. 创建人账号被停用期间，其全部密钥失效；账号恢复启用后自动恢复。创建人账号被删除后，其密钥永久失效。创建人的角色不再拥有"API 密钥"功能权限时，其密钥同样失效。
  8. 密钥过期后状态显示"已过期"，调用被拒绝；延长过期时间后恢复。
  9. 管理员审计（推荐假设，见 Q-12）：拥有"API 密钥审计"权限的用户，可以在数据范围内（按创建人所属组织计算）查看他人密钥的列表（不含明文和检索结果）及其调用日志，可以**停用或删除**他人密钥，但不能编辑、启用或重新生成。被管理员停用的密钥，创建人不能自行启用，状态显示"已被管理员停用"。
  10. 状态：启用 / 停用 / 已被管理员停用 / 已过期 / 创建人不可用 / 无可检索知识库（后三种由系统计算）。
- 关联验收：AC-52 ~ AC-55、AC-70 ~ AC-73

### F-18 开放检索 API
- 描述：业务系统持 API 密钥调用，对检索范围内的一个知识库进行检索，返回相关分段。
- 业务规则：
  1. 调用方不需要登录账号，只凭 API 密钥鉴权。
  2. 每次调用指定一个知识库。
  3. 请求参数（业务含义）：

     | 参数 | 必填 | 规则 |
     |---|---|---|
     | 知识库标识 | 是 | 必须在密钥当前的检索范围内 |
     | 查询文本 | 是 | 1 ~ 1000 字 |
     | 检索方式 | 否 | 向量 / 全文 / 混合；不传时使用知识库默认设置 |
     | Top K | 否 | 1 ~ 20；不传时使用知识库默认值 |
     | Score 阈值 | 否 | 0 ~ 1；不传时使用知识库默认值 |
     | 是否 Rerank | 否 | 不传时使用知识库默认值 |

  4. 返回命中结果列表，按得分降序。每条包含：内容、得分、分段标识、分段序号、关键词、所属文档标识与文件名、所属知识库标识与名称、分段类型（通用 / 父块）。父子分段时，内容为父块全文，另附命中的子块列表（子块内容与得分）。同时返回本次实际使用的检索参数。
  5. 只返回"可用 + 启用"文档中处于"启用"状态的分段。
  6. 错误场景需返回可区分的错误类型和中文说明：
     - 密钥缺失或无效；
     - 密钥已停用（含被管理员停用、创建人不可用）；
     - 密钥已过期；
     - IP 不在白名单；
     - 知识库不存在或未授权（两者不区分）；
     - 参数不合法；
     - 调用超限；
     - 模型服务不可用。
  7. 平台提供"API 文档"页面，展示调用地址、鉴权方式和请求/返回示例。示例由架构师按最终契约提供。
  8. 每次调用都实时按创建人当前的权限判断知识库是否在范围内。
- 关联验收：AC-56 ~ AC-60

### F-19 API 调用日志与限流
- 描述：记录每次开放 API 调用，并按密钥限流。
- 业务规则：
  1. 每次调用记录：时间、密钥名称及前缀、创建人、知识库、查询文本原文（Q-08 已确认）、返回条数、耗时（毫秒）、结果（成功 / 失败类型）、调用方 IP。
  2. 调用日志页的查询条件：时间范围（默认近 7 天，最长 90 天）、密钥、知识库、结果；列表按时间倒序。
  3. 密钥列表中展示每个密钥近 7 天的调用量和失败数。
  4. 可见范围：员工只能看自己密钥的调用日志；管理员按数据范围查看（F-17 规则 9）。日志保留 180 天。
  5. 限流：单个密钥在一分钟内的调用次数超过其上限时，超出部分被拒绝，返回"调用超限"，下一分钟恢复。
  6. 无法识别密钥的调用失败记录，只有集团管理员和超级管理员可见。
- 关联验收：AC-61 ~ AC-62

### 5.3 关键流程

1. 系统开荒：超级管理员首次登录改密 → 配置 Embedding 模型（测试通过并设为默认）→ 建立组织树 → 创建子公司管理员并分配"公司管理员"角色 → 子公司管理员建部门和员工。
2. 建库到可检索：员工创建知识库 → 上传文件，选择通用或父子分段并预览 → 保存并处理 → 状态变为"可用" → 召回测试验证 → 调整分段或检索设置。
3. 分配使用：所有者把知识库分配给部门（只读）和指定同事（可编辑）→ 部门成员在"我的知识库"中看到并使用。
4. 开放给外部系统：员工在"我的 API 密钥"中创建密钥（范围为全部可访问，或指定知识库）→ 复制密钥交给对接方 → 对接方按 API 文档调用 → 员工在调用日志中查看调用情况。
5. 离职交接：管理员停用账号 → 该账号会话和 API 密钥立即失效，其知识库照常可被已分配人员使用，并标记为"待交接" → 管理员在知识库管理视图中把其名下知识库批量转移给接任者 → 接任者按需重新创建自己的 API 密钥。

## 8. 非功能需求（只写有明确要求的）

- 架构诉求（用户明确提出，方案由架构师设计）：权限认证、知识库管理、知识库检索（含开放 API）、用户与模型聊天（二期）、后台文档处理应能**独立部署、独立扩展**，某一部分扩容或故障时不需要整体重新部署；后续新增的业务模块能复用统一的认证与权限能力。
- 数据量级（Q-06 已确认）：组织节点 ≤ 5,000；用户 ≤ 20,000；知识库 ≤ 2,000；单知识库文档 ≤ 10,000；全平台分段 ≤ 500 万（父子分段按子块计）。
- 性能（推荐假设，不含模型服务自身的耗时波动）：
  - 管理端列表查询 P95 ≤ 1 秒。
  - 开放检索 API（单知识库 ≤ 10 万分段，不开 Rerank）P95 ≤ 1.5 秒；开启 Rerank 时 P95 ≤ 3 秒。
  - 开放检索 API 全平台支持 ≥ 50 次/秒的并发调用。
  - 一个 10 MB 的文本型 PDF，在模型服务正常时 10 分钟内处理完成。
  - 权限变化（分配移除、账号停用、密钥停用）对开放检索 API 的生效延迟 ≤ 5 秒（推荐假设 A-24）。
- 安全：
  - API 密钥、模型凭据不能以明文出现在列表、日志和操作日志的变更摘要中。
  - 文档原文件只允许有日常访问权限的用户下载。
- 审计 / 操作日志：见 F-06、F-19，保留 180 天。
- 可用性：平台重启后，文档处理任务可以恢复或明确标记失败（F-12）。

## 9. 验收标准

### AC-01（F-01）账号密码登录成功
- Given：已启用账号 `zhangsan`，密码正确，所属组织为启用状态
- When：在登录页输入账号密码并登录
- Then：进入首页，左侧只显示该用户有权限的菜单；登录日志新增一条"成功"记录

### AC-02（F-01）密码错误与锁定
- Given：账号 `zhangsan` 存在
- When：15 分钟内连续 5 次输入错误密码，第 6 次输入正确密码
- Then：前 5 次均提示"账号或密码错误"；第 6 次提示账号已锁定及剩余时间，无法登录；锁定 15 分钟后可以正常登录。输入不存在的账号时，同样提示"账号或密码错误"

### AC-03（F-01）停用账号/停用组织不可登录
- Given：账号 A 为停用状态；账号 B 为启用状态，但其上级公司被停用
- When：分别用 A、B 的正确密码登录
- Then：均登录失败，并提示账号不可用；登录日志记录失败原因

### AC-04（F-01）会话续期与失效
- Given：用户已登录，访问令牌已过期，但距上次使用不满 7 天
- When：用户点击任一列表的查询
- Then：请求成功返回数据，用户无感知。如果该会话已被吊销，则跳转登录页，重新登录后回到原页面

  - 所有直接请求都被拒绝，提示"无权限或数据不存在"；
  - U 在知识库管理视图中仍只看到自己拥有的知识库（不受组织树例外的影响）

### AC-76（F-05、F-04）多角色数据范围与功能来源无关
- Given：用户 V 属于 A 公司研发部，持有角色 R1（功能：用户管理 - 查看；数据范围 DEPT）和 R2（功能：仅知识库管理视图；数据范围 COMPANY）；A 公司测试部有用户 Z
- When：V 打开用户管理并查询 Z；之后停用 R2，V 刷新后再次查询；管理员打开 R1 的"分配权限"抽屉
- Then：R2 启用时，V 在用户管理中能看到 Z（数据范围取并集 COMPANY，作用于来自 R1 的用户管理功能）；停用 R2 后看不到 Z，而且 V 的菜单中不再有知识库管理视图；分配权限抽屉的数据范围区域显示提示"用户拥有多个角色时，数据范围取所有启用角色的并集，并对该用户拥有的所有功能生效。"
