# 界面视觉方案（v1，2026-11-13）

> 来源：用户验收反馈"页面需要美化"，按 `/frontend-design` 审视整体后由主会话制定。本方案只改视觉与文案呈现，**不改交互流程、接口与权限逻辑**。

## 1. 设计对象

- 产品：集团内部的知识库管理平台。把制度、手册、表格等资料整理成可检索的知识库，并按组织分配访问权限、通过 API 密钥对外提供检索。
- 使用者：知识库所有者与编辑者（日常上传、维护分段）、各级管理员（组织、角色、审计）、调用开放接口的开发者。
- 主要任务：找到知识库 → 管理文档与分段 → 验证检索效果。界面是"每天要用的工具"，克制、清晰、信息密度适中优先，不做营销式页面。

## 2. 设计主题：书脊

知识库就是一排书。全站只在一个地方用力：**"书脊"母题**。

- **品牌标识**：几本高低不一的书脊竖排组成的简单 SVG 标识，用在顶栏和登录页。
- **知识库卡片**：左侧有一条 6px 宽的"书脊"色带，颜色由知识库图标决定，从下文的书脊色板中按图标确定性取色。
- **知识库详情左栏**：顶部同样用书脊色带呼应。

除此之外的地方保持安静：表格、表单、抽屉沿用 antd 结构，只换 token。

## 3. 色彩

| 名称 | 色值 | 用途 |
|---|---|---|
| 墨 | `#1E2A32` | 正文主色、顶栏背景 |
| 青（主色） | `#0E6E6E` | 主按钮、链接、选中态（antd `colorPrimary`） |
| 纸 | `#F5F7F6` | 页面背景（冷调近白，**不用暖米色**） |
| 白 | `#FFFFFF` | 卡片、表格、表单表面 |
| 霜 | `#E2E7E4` | 分隔线、边框（`colorBorderSecondary`） |
| 藤黄（标记） | `#F2C14E` | **只用于**检索命中的高亮底色（召回测试结果中的命中词、得分条） |

- 书脊色板（8 色，低饱和，只用于书脊色带与知识库图标底色）：
  - `#0E6E6E`、`#3D5A80`、`#7A5C3E`、`#5B6C3A`、`#7B4B6A`、`#2F6F8F`、`#8A6D1F`、`#4E5D6C`
- 状态色沿用 antd 语义色（成功/警告/错误），只把 `colorInfo` 对齐主色。
- 不用渐变、不用彩色阴影，阴影只在悬浮层（下拉、弹窗）出现。

## 4. 字体

**不引入网络字体**，因为内网和离线环境必须可用。字体只通过字体栈选择：

- **标题**（页面标题、知识库名、登录页标语）用宋/衬线栈：`"Noto Serif SC", "Source Han Serif SC", "Songti SC", "STSong", serif`，字重 600。衬线标题是这个"资料馆"主题的个性来源。
- **正文与界面**用无衬线栈：`"PingFang SC", "HarmonyOS Sans SC", "MiSans", "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif`，基准 14px，行高 1.6。
- **数字**（统计、得分、计数）：`font-variant-numeric: tabular-nums`。
- 字号阶梯：12 / 14 / 16 / 20 / 24 / 30。只有页面标题用 20–24，登录页标语用 30。
- 禁用：全大写标签、标题里单独给一个词换色或加粗、标题上方的小字"眉标"。

## 5. 布局

- **ProLayout**：
  - 维持 `mix` 布局；顶栏用"墨"色背景、白字，左侧为品牌标识加"知识库平台"（衬线）。
  - 侧栏为白底，选中项用"青"色左边线与浅青底（`#0E6E6E` 的 8% 透明度）表示，不用整块填充。
  - 内容区背景为"纸"色。
- **页面标题**：PageContainer 标题用衬线 20px；`extra` 主操作靠右。
- **登录页**：左右分栏，窄屏时上下堆叠。
  ```
  ┌───────────────────────────┬──────────────────┐
  │ 墨色面板                   │                  │
  │  [书脊标识，大号]          │   登录            │
  │  知识库平台（衬线 30）      │   账号 [______]   │
  │  一句产品说明（正文 16）    │   密码 [______]   │
  │                           │   [ 登录 ]        │
  └───────────────────────────┴──────────────────┘
  ```
  左侧文案示例："把制度、手册和表格整理成可以检索的知识库。"不写口号，不放假数据。
- **知识库卡片**：去掉 `hoverable` 的整体浮起阴影，改为以下结构：
  - 左侧书脊色带
  - 1px "霜"色边框
  - 悬停时边框变"青"
  - 键盘聚焦时显示清晰的 focus 环

  卡片内容层级：
  - 名称：衬线 16
  - 描述：两行
  - 一行标签：保留现有标签，减少颜色种类，只有"处理中/失败/模型停用"带语义色，其余用中性灰描边
  - 统计：tabular-nums
  - 所有者与更新时间
- **知识库详情**：左栏信息卡顶部加书脊色带；分段、召回结果卡片保持朴素。召回测试结果中的命中内容用"藤黄"高亮，这是藤黄唯一出现的地方。
- **空状态文案**：说明下一步该做什么，比如"还没有知识库。创建一个，然后上传第一份文档。"不用"暂无数据"这类空话（全局 `renderEmpty` 可保留"暂无数据"作兜底）。

## 6. 质量底线

- 键盘可达：所有可点击的卡片都要有 `tabIndex`、`role` 和回车触发，焦点环清晰。
- `prefers-reduced-motion` 时关闭非必要过渡。全站不加入场动画，只保留 antd 自带的交互反馈。
- 对比度：正文对背景 ≥ 4.5:1。主色 `#0E6E6E` 上的白字满足 AA。
- 最小宽度 1280 下布局不挤压；登录页在 375 宽时可用。

## 7. 自检（相对通用默认的取舍）

- 色彩：没有用 antd 默认蓝 `#1677ff`，也没有用"暖米色加陶土色"或"黑底加荧光色"。主色"青"与"藤黄"标记对应"资料与批注"，主题相关。
- 卡片：没有把所有内容都做成同一种圆角卡片。只有知识库卡片带书脊，表格页保持表格。
- 字体：用衬线标题加无衬线正文，并且不依赖网络字体。这是针对内网工具的选择。
- 只有一处记忆点（书脊），其他地方克制。

## 实现说明（frontend-dev，2026-11-13）

落地文件（均在 `frontend/src/`）：
- `theme.ts`：antd token（青主色、墨正文、纸背景、霜边框、字体栈）与 Table/Menu/Layout 组件 token；导出 `COLORS`、字体栈常量。
- `styles/global.css`（在 `main.tsx` 引入）：tabular-nums、页面标题衬线 20px、`mark` 藤黄、顶栏/侧栏选中态补充、`prefers-reduced-motion`、`body { margin: 0 }`。
- `components/BrandMark.tsx`（书脊 SVG）、`components/spineColor.ts` + `spineColor.test.ts`（8 色色板、按图标名哈希取色的纯函数）。
- `layouts/BasicLayout.tsx`：logo、ProLayout `token`（墨色顶栏、浅青选中底）。
- `pages/auth/AuthShell.tsx` + `AuthShell.module.css`：登录与改密共用的左右分栏外壳（<=768px 上下堆叠）。
- `pages/kb/list/components/DatasetCard.tsx` + `.module.css`：书脊色带、1px 霜边框、悬停青边、`role="link"` / `tabIndex` / Enter、空格触发、focus-visible 环、标签减色。
- `pages/kb/detail/Layout.tsx`：左栏顶部书脊色带、图标使用书脊色。
- `pages/kb/detail/recall/components/RecallResultList.tsx`：得分条（藤黄填充），命中内容 `mark` 为藤黄。
- 空状态文案：知识库列表、文档列表（有上传权限时）、API 密钥列表。

与方案的偏差及理由：
1. 登录表单标题由“知识库平台”改为“登录”：品牌名已在左侧面板，避免重复；E2E 与单测均未引用该文案。
2. 召回结果的“得分 x.xx”从蓝色 Tag 改为文字加藤黄得分条（得分按 0~1 截断）；命中高亮沿用现有父子块高亮逻辑（`mark`），`keywords` 仍以中性 Tag 展示，没有新增高亮逻辑。
3. 卡片由 antd `Card` 改为自绘 `div`，以实现书脊与键盘可达；卡片名称改为 `aria-label="打开知识库 <名称>"`。
4. 沙箱无衬线中文字体，截图中标题回退为无衬线；真实环境按字体栈取宋体/思源宋体。
5. 截图使用 Playwright `page.route` 拦截 `/api/v1/**` 的模拟数据（按协调方要求不登录 admin），模拟脚本不进仓库。

受影响的 E2E 选择器（E2E 不在 git 内）：登录页标题文本“知识库平台”改为“登录”；知识库卡片可通过 `role=link` 访问；其余文案仅改了空状态描述（保留“还没有可访问的知识库”“还没有文档，点击右上角”“还没有 API 密钥”前缀）。
